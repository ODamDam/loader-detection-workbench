2. 핵심 결과와 판정

가설(FND-0016): 인코딩된 PowerShell로 예약 작업을 등록해 지속성을 확보한다 — 판정: 지지됨(supported)

  • 등록된 작업의 실행 대상이 샘플이 쓴 파일의 경로와 같다. 인코딩된 명령과 파일이 한 지속성 단계로 이어진다(FND-0017).
  • 작업은 등록 시점에 한 번 시작하고 5분마다 반복하도록 설정됐다(FND-0013).
  • 판정 범위: 작업 등록과 파일 작성까지만 해당한다. 60초 제한 전에 작업이 파일을 실행한 기록은 없다.

인코딩된 명령은 문자열로만 해독했고 실행하지 않았다.

4. 작동 원리(관측한 단계, FND-0018)

  1. .NET 스텁이 메모리에서 페이로드를 복호화하는 것으로 추정한다. 정적 API 이름에서 추론했으며 관측하지 않았다.
  2. 인코딩된 PowerShell로 예약 작업을 등록한다.
  3. 작업이 가리키는 파일을 %APPDATA%에 쓴다. 이 파일이 샘플의 복사본인지는 확인하지 않았다.

6. 한계와 확인하지 못한 것

  • 성공한 실행은 1회, 최대 60초의 관측이다. 5분 간격의 작업 실행은 관측 시간 밖에 있다.
  • 작성된 파일의 정체와 복호화 과정은 확인하지 않았다.
  • 네트워크를 차단했으므로 통신 기능의 동작은 확인하지 않았다.
  • 정상 비교는 YARA 2건, Sigma 5건의 Case로 적고 정상 설치 프로그램이 없다.
