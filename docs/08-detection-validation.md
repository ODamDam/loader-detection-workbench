# 탐지 가설과 룰 검증 설계

## 1. Detection Hypothesis

탐지 가설은 다음 항목을 포함한다.

- 분석 대상과 초기 실행 범위
- 정적 PE 근거
- 동적 이벤트 근거
- 정상 대응 행위
- YARA 룰
- Sigma 룰
- 오탐 가능성
- 적용 한계
- 신뢰도
- 사용자 승인 상태

## 2. YARA 검증

1. 룰 문법 검사
2. 목표 악성 또는 시뮬레이터 파일 검사
3. 사례별 정상 대응 파일 검사
4. 공통 정상 파일 모음 검사
5. 매치 문자열과 조건 기록
6. 오탐 원인 기록
7. 버전 승인

## 3. Sigma 검증

1. YAML·구조 검사
2. Sigma 문법 검사
3. 지원 백엔드 변환 가능 여부 검사
4. 정규화 이벤트에 조건 적용
5. 목표 악성 이벤트 탐지 확인
6. 사례별 정상 대응 로그 시험
7. 공통 정상 로그 시험
8. 오탐 이벤트와 조건 기록
9. 버전 승인

실제 SIEM 적재는 확장 후보이다.

## 4. 정상 데이터 전략

### 초기
- Windows 기본 프로세스 활동
- 일반 파일·레지스트리 작업
- 정상 PowerShell 명령
- 시뮬레이터 정상 모드

### 최종
- 공통 정상 데이터셋
- 각 악성 사례와 유사한 정상 설치·업데이트·다운로드 대응 데이터

## 5. 룰 상태

```text
DRAFT
→ CANDIDATE
→ TESTING
→ REVISION_REQUIRED
→ VALIDATED
```

## 6. 검증 완료 기준

다음 항목을 모두 충족해야 한다.

- 문법·구조 검사를 통과한다.
- 목표 악성 사례를 탐지한다.
- 사례별 정상 대응 데이터를 시험한다.
- 공통 정상 데이터셋을 시험한다.
- 핵심 조건이 실제 근거와 연결된다.
- 오탐 가능성과 적용 한계가 기록된다.
- 데이터셋 버전과 룰 버전이 저장된다.
- 사용자가 최종 승인한다.

## 7. 평가 지표

- TP
- FP
- FN
- Precision
- Recall
- F1
- Evidence-link ratio
- 룰 수정 횟수
- 분석·검증 소요 시간
- 룰 버전별 성능 변화

Precision·Recall·F1은 비교 자료로 사용하며, 소규모 데이터셋에서 절대적 합격 임계값으로 사용하지 않는다.

## 8. AI 모드

### 기본 모드
AI가 탐지 가설과 룰 초안을 제안하고 Workbench가 자동 검증한다. 최종 채택은 사용자가 승인한다.

### 실험 모드
AI가 검증 실패와 오탐 원인을 바탕으로 제한된 횟수만큼 룰을 수정하고 재검증한다. 모든 버전과 수정 이유를 보존한다.
