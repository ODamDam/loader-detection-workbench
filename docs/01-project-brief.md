# 프로젝트 개요서

## 1. 공식 과제명

**Windows 악성코드 로더의 초기 실행 행위 분석 및 탐지 룰 검증 프레임워크 구축**

## 2. 소프트웨어 산출물

가칭 **Local Detection-as-Code Workbench**이다.

## 3. 문제 정의

Windows 악성코드 로더의 초기 실행 행위는 프로세스 생성, 파일 드롭, 레지스트리 변경, DNS·네트워크 연결 등 여러 증거로 분산된다. 단일 로그나 단일 IOC만으로는 정상 설치·업데이트 행위와 구별하기 어렵다.

본 프로젝트는 정적 PE 정보와 초기 실행 로그를 하나의 케이스로 구조화하고, 탐지 가설을 중심으로 YARA와 Sigma를 연결한 뒤, 악성·정상 데이터에서 반복 검증하는 로컬 프레임워크를 구축한다.

## 4. 대상 사용자

### 단기 사용자
- 프로젝트 수행자 본인
- 지도교수 및 심사·발표 평가자

### 장기 사용자
- Windows 악성코드 분석을 학습하는 보안 학습자
- 소규모 분석 환경에서 탐지 룰을 검증하려는 분석가
- 재현 가능한 포트폴리오를 구축하려는 연구·교육 사용자

## 5. 핵심 가치

- 증거 기반 분석
- 정상 반례 기반 오탐 검증
- YARA·Sigma 연계
- AI 비의존 동작
- 폐쇄형 반복 검증
- 재현 가능한 케이스 단위 산출물
- 안전한 로컬 실행과 공개

## 6. 연구 질문

1. Windows 악성코드 로더의 초기 실행 구간에서 반복되는 프로세스·파일·레지스트리·네트워크 행위는 무엇인가.
2. 관찰한 행위를 YARA와 Sigma로 어떻게 표현할 수 있는가.
3. YARA와 Sigma는 어떤 증거 유형을 탐지하는 데 각각 적합한가.
4. 정상 설치·업데이트 행위와 악성 로더 행위를 어떤 조건으로 구별할 수 있는가.

## 7. 성공 기준

### 정량 기준
| 지표 | 목표 |
|---|---:|
| 분석 케이스 | 6개 이상 |
| YARA 룰 | 6개 이상 |
| Sigma 룰 | 6개 이상 |
| 개별 분석 보고서 | 6편 이상 |
| 최종보고서 | 1편 |
| 논문 초안 | 1편 |

### 제품 기준
- 최소 1개 케이스가 입력부터 보고서 생성까지 완주한다.
- 6개 케이스가 동일한 스키마로 관리된다.
- 각 케이스에 최소 1개 YARA·Sigma 룰 쌍이 연결된다.
- 룰은 악성·정상 데이터에서 검증되고 근거와 한계가 기록된다.
- 독립형 HTML 보고서와 정적 보고서 사이트가 생성된다.

## 8. 프로젝트 범위

### 포함
- Windows PE `.exe` 중심 초기 실행 분석
- 정적 PE 분석
- Sysmon 필수 수집
- 선택적 Procmon·PCAP 수집
- YARA·Sigma 룰 생성·편집·검증
- AI Provider 추상화
- CLI와 로컬 웹 UI
- VMware 기반 단일 Windows 분석 VM 자동화
- Markdown·HTML 케이스 보고서
- 공개용 정제 데이터 번들

### 제외
- 범용 악성코드 샌드박스
- 다중 테넌트 서버
- 무제한 외부 인터넷 접속
- 자동 룰 배포
- AI 단독 최종 승인
- 실제 악성 샘플 공개
- 최종보고서·논문 초안 자동 통합 작성
