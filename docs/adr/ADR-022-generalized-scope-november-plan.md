# ADR-022: 범용 악성코드 대상과 11월 최종 구현 범위

## 상태

승인 — 2026-11-11 사용자 결정. 근거: 2026-10-25 제출 중간보고서와 과제명 변경 신청서,
2026-10-14 지도교수 면담 피드백.

## 배경

과제명이 「다중 증거 기반 Windows 악성코드 분석 지원 플랫폼 구축」으로 변경 신청되었고,
분석 대상이 로더·다운로더의 초기 실행에서 다양한 Windows 악성코드 패밀리로 확대되었다.
기존 문서(README, `docs/project-decisions.json`, 샘플 Protocol v1)는 로더 한정과
dev 12–16 + eval 6–8 규모를 전제로 하여 최신 공식 기록과 충돌한다.

## 결정

1. 분석 대상은 다양한 Windows 악성코드 패밀리이다. 상세 분석(dev) 6건과 별도 Unseen
   평가군 약 4–6개를 둔다.
2. Dev/Unseen 분할은 상세 행위 분석 전에 수행하고, Unseen 구성원은 target behavior로
   선별하지 않는다. 동결된 룰만 Unseen에 적용하며, 이후 수정본의 Unseen 결과는
   tuning으로 분리 기록한다.
3. 실제 샘플은 사용자가 공개 저장소에서 직접 확보하고, 네트워크를 차단한 분석 VM에서만
   실행한다. 실행 전후 클린 스냅샷 자동 복원을 구현하며, 복원을 확인할 수 없으면 다음
   실행을 차단한다.
4. 정상 비교 데이터는 VM에서 정상 시나리오를 실행해 직접 수집한다.
5. YARA는 `yara-python`, Sigma는 pySigma 파싱과 자체 오프라인 평가기를 사용한다(ADR-005의
   구현 방식 확정, ADR-023).
6. 선택 범위: 증거 관계·가설 시각화 UI, 단일 LLM 분석 보조, 다중 LLM 비교(Claude·GPT·
   Gemini). 대화형 AI Agent는 제외한다. LLM이 없어도 핵심 파이프라인은 동작해야 한다.
7. 기능 동결은 2026-11-22이며, 11/23–29는 Unseen 평가·버그 수정·문서화만 수행한다.

## 결과

- 공식 명칭과 범위 문서를 갱신한다. 저장소 이름 `loader-detection-workbench`는 유지하며
  변경 여부는 별도로 결정한다.
- 샘플 Protocol v1의 bias 통제 원칙은 유지하되 대상 모집단과 규모는 본 ADR을 따른다.
- 기존 Sample Intake의 로더 screening 필드는 하위 호환을 위해 남기며, 범용 대상에서는
  해당 필드를 `not_applicable`로 기록할 수 있다.
