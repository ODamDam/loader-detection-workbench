# ADR-033: AI 의견의 한국어 읽기용 번역

## 상태

승인 — 2026-11-19 사용자 승인("(A)로 승인한다"). 외부 전송 데이터 범위 확대를 포함한다.
근거: ADR-026(AI 보조, 구조 요약 범위), ADR-031(Provider 3종, 두 단계 게이트, Case 작업 공간).

## 배경

Case 작업 공간의 AI 의견은 영어 장문이라 검토할 때 피로가 크다. 사용자는 의견 위에 마우스를
올리면 한국어 번역이 보이기를 원했다. 선택지는 (A) Provider로 번역해 저장, (B) 브라우저 내장
번역 API였고, 사용자가 (A)를 골랐다.

## 결정

1. **전송 범위 확대:** 기존 범위 (가)(구조 요약)에 "저장된 AI 의견의 번역 전송"을 더한다.
   보내는 것은 의견마다 순번, 제목, 본문뿐이다. 이 문장들은 이미 승인된 구조 요약에서 나온 모델
   출력이며, 샘플 바이트, 원본 로그, 확정 사항 문장, 지표 값은 보내지 않는다.
2. **같은 게이트:** `[ai] allow_network = true`, 키 환경 변수, 명령의 `--allow-network`가 모두
   있어야 호출한다. 기본 Provider는 DeepSeek(가장 저렴)이고 `--provider`로 바꿀 수 있다.
   `workbench ai translate AIA-NNNN|CASE-NNNN`.
3. **검증(fail closed):** 요청한 순번이 정확히 한 번씩 돌아와야 하고, 원문의 Workbench ID
   (ART·FND·SMP·RULE·CASE·HYP·AIA·VMR·BMK)가 모두 그대로 있어야 한다. 링크, 실행 명령 형태,
   제어 문자, 빈 문장, 길이 초과는 거부한다. 하나라도 어기면 아무것도 저장하지 않는다.
4. **저장:** AI 스키마 v3의 `ai_translations`(추가 전용, 수정·삭제 금지 트리거). 의견마다
   언어 `ko` 하나, Provider·모델·요청 SHA-256·시각을 함께 둔다. 이미 번역된 의견은 다시 보내지
   않는다. v2 데이터베이스는 읽기는 그대로, 첫 쓰기에서 표만 추가된다.
5. **표시:** 작업 공간 AI 탭에서 번역이 있는 의견에 `KO` 표시를 붙이고, 마우스를 올리거나
   키보드로 초점을 주면 번역이 뜬다(CSS만, 스크립트 없음, 기존 CSP 유지). 번역 아래에 "읽기용
   기계 번역, 기록은 영어 원문"을 적는다.
6. **원문 우선:** 비교 표, 같은 의견 판정, 채택(`finding adopt`), 보고서는 모두 영어 원문만
   쓴다. 번역은 어떤 계산이나 참조의 입력도 아니다.

## 결과

- 비용은 분석 1건당 호출 1회, 의견 십여 개 분량이라 매우 작다.
- 번역 오류는 원문으로 확인해야 한다. ID 보존은 검사하지만 의미의 정확성은 보장하지 않는다.
- `project validate`가 번역이 존재하는 의견을 가리키는지, 언어와 요청 해시 형식을 검사한다.
