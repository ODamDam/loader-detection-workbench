# ADR-027: 다중 Provider 분석 비교 (W8)

## 상태

승인 — 2026-11-17 사용자 지시("전체 프로젝트의 빠른 구현을 목표로 최대한 진행")에 따른
구현. 근거: 11월 최종 구현 계획 v1의 W8(대안 B), ADR-026.

**이 결정이 다루지 않는 것:** 외부 Provider(Claude·GPT·Gemini) 연결과 외부로 보낼 데이터
범위. 이 결정은 그 승인 없이 동작하는 비교 구조만 정한다.

## 배경

W8은 여러 LLM이 같은 입력을 독립적으로 분석하고, 공통 의견과 개별 의견을 나눠 통합
보고서를 만드는 것이다. 외부 Provider는 아직 승인되지 않았지만, 비교 로직은 Provider와
무관하게 만들 수 있다.

## 결정

1. **저장된 분석만 비교한다:** `ai.compare`는 Provider를 호출하지 않는다. 이미 저장된
   분석 기록(ADR-026)을 읽어 비교한다. 새 테이블이 없고 저장 형식도 바꾸지 않는다.
2. **같은 입력만 비교한다:** 비교 대상은 같은 Case, 같은 입력 SHA-256이어야 하고 Provider당
   분석 하나여야 한다. 아니면 `INVALID_AI_REQUEST`로 거부한다. 기본 선택은 Case의 가장
   최근 입력에 대해 Provider별 가장 최근 분석이다.
3. **같은 의견의 기준:** 종류가 같고, 인용한 Artifact 집합이 같고, 문구(가설은 제목, 검토
   항목은 본문)의 토큰 Jaccard 유사도가 0.5 이상이면 같은 의견으로 묶는다. 두 Provider
   이상이 낸 묶음은 공통 의견, 나머지는 개별 의견이다. 의미 판단이 아닌 투명한 휴리스틱이며,
   보고서와 CLI는 묶음의 구성원 전체를 보여줘 사람이 확인할 수 있게 한다.
   - **개정(2026-11-18, ADR-031 실제 호출 결과):** 실제 세 모델이 같은 내용을 다른 문구로 내
     위 기준으로는 공통 의견이 0개였다. 기준을 다음으로 바꿨다. 서로 다른 Provider, 같은
     종류, **인용 ID가 하나 이상 겹침**, 그리고 **행위 주제 집합**(network, execution,
     registry, script, screen, anti_analysis, injection, credentials; 고정 키워드)이 절반 이상
     겹침. 주제는 가설형은 제목, 나머지는 본문에서 읽는다. 주제가 없으면 기존 문구 Jaccard
     0.5를 쓴다. 묶음은 구성원 **모두와** 맞아야 들어간다(연쇄 병합 방지). 같은 실제 데이터에서
     공통 의견 9개(가설은 네트워크·드롭/실행·레지스트리·화면 캡처)로 묶였다. 다른 주제가 함께
     언급된 검토 항목은 느슨하게 묶일 수 있다.
4. **표시:** `workbench ai compare CASE [--analysis AIA ...]`. 보고서의 AI 섹션에 두 Provider
   이상의 분석이 있으면 "Provider Comparison" 표를 붙인다. 추론이라는 표시는 그대로 둔다.
5. **검토는 기존 경로:** 비교는 제안의 검토 상태를 바꾸지 않는다. 가설 반영은 여전히 각
   분석의 `ai accept`로만 한다.

## 결과

- 외부 Provider가 승인되면 어댑터만 추가하면 된다. 비교와 보고서는 바뀌지 않는다.
- 지금은 오프라인 Provider가 하나뿐이라 실제 비교는 시험용 Provider로만 확인했다.
- 유사도 기준은 영문 토큰 기준이다. 다른 언어로 답하는 Provider가 생기면 기준을 다시 본다.
