# ADR-029: 비식별화한 정적 보고서 사이트 (M4)

## 상태

승인 — 2026-11-17 사용자 지시("다음 작업 진행")에 따른 구현. 근거: ADR-011(Markdown·
독립형 HTML·정적 사이트), ADR-012(공개 범위), ADR-025(블록 문서 보고서).

**이 결정이 다루지 않는 것:** 사이트를 실제로 공개하는 일(Publication Bundle 공개는 사용자
승인 대상)과 Publication Bundle 형식.

## 결정

1. **명령:** `workbench report site OUTPUT_DIR`. Project의 모든 Case를 한 번에 만든다.
   - `index.html`: Project 개요, 정량 목표(분석 악성 Case·동결 YARA·동결 Sigma·보고서, 각
     목표 6), Case 목록과 링크, 룰별 최신 검증 결과(분모 포함)
   - `rules.html`: 룰별 버전 이력, 보고 대상 버전 본문(최근 동결, 없으면 최신 초안), 검증
     실행 표
   - `cases/CASE-NNNN.html`: `report build`와 같은 블록 문서 + 사이트 색인 링크
2. **같은 문서 모델:** 사이트도 ADR-025의 블록 문서를 독립형 HTML로 렌더링한다. script와
   외부 자원이 없고 CSP `default-src 'none'`을 유지한다. 페이지 사이 이동을 위해 `Links`
   블록을 추가했다. 링크 대상은 Workbench가 만든 상대 `.html` 경로만 허용하고(정규식
   검사), 증거 문자열은 링크가 될 수 없다.
3. **항상 비식별화:** 사이트는 공유하려고 만드는 산출물이므로 모든 페이지의 신뢰하지 않는
   문자열과 코드 블록에 `report.redact`를 적용한다.
   - 사용자 프로필 경로(`X:\Users\<name>`, `\Device\HarddiskVolumeN\Users\<name>`)의 이름 →
     `<user>`. `Public`·`Default` 같은 기본 프로필은 남긴다.
   - 도메인 SID(`S-1-5-21-…`) → `S-1-5-21-<sid>`
   - Sysmon `Computer` 값과 `User`·`SourceUser`·`TargetUser` 필드(`호스트\사용자`)에서
     배운 호스트·사용자 이름 → 어디에 나오든 단어 단위로 `<host>`·`<user>`
   - 본문의 `a\b` 모양을 계정으로 추측하지 않는다. 레지스트리 경로 조각을 호스트로 오인한
     사례가 실제 데이터에서 확인됐다.
   - Workbench가 만든 값(표시 ID, 개수, 해시)은 바꾸지 않는다.
4. **기존 보고서는 그대로:** `report build`는 비식별화하지 않는다. 분석자가 로컬에서 보는
   원본 보고서다.
5. **출력:** 대상 디렉터리가 이미 있으면 `REPORT_OUTPUT_EXISTS`로 거부한다. 옆에 만든 임시
   디렉터리에 모두 쓴 뒤 이름을 바꾸므로 실패하면 아무것도 남지 않는다. 명령은 치환 수를
   출력하고 공개 전에 검토하라고 안내한다.

## 결과

- 2026-11-17 검증용 Project(실제 VM 수집 이벤트 포함): 5페이지, 치환 6,500건. 게스트
  사용자명·호스트명·SID가 남지 않았고 script·외부 링크가 없음을 확인했다.
- 패턴 기반이므로 알려진 위치에 한 번도 나오지 않는 이름은 찾지 못한다. 공개 전 사람의
  검토가 필요하다.
- 분석 VM 이름이 게스트 호스트 이름과 같으면 VM 실행 표의 VM 이름도 `<host>`로 바뀐다.
- 행위·ATT&CK 태그 필터, 다운로드 자료, Publication Bundle은 아직 없다.
