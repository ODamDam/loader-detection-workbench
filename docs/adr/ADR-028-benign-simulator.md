# ADR-028: 무해한 시뮬레이터 실행 파일과 빌드 방식 (M5)

## 상태

승인 — 2026-11-17 사용자 승인("그렇게 진행": Windows 내장 C# 컴파일러로 빌드, 실제 VM에서
sample 경로 1회 실행). 근거: ADR-006(단일 실행 파일·내장 프로필), ADR-016(EXE 우선),
ADR-024(VM 실행 런).

## 배경

sample 실행 경로(`vm run`)는 실제 악성 샘플을 넣기 전에 무해한 실행 파일로 먼저 검증해야
한다. 실패했을 때 원인이 샘플인지 실행기인지 가를 수 있어야 한다. 로드맵 M5는 시뮬레이터
Case 하나가 전체 파이프라인을 완주하는 것을 종료 조건으로 둔다.

## 결정

1. **형식:** C# 단일 콘솔 실행 파일 `workbench-simulator.exe`(x64 PE). 소스는
   `tools/simulator/WorkbenchSimulator.cs`에 두고, 실행 파일은 `build/`(git 제외)에 만든다.
   실행 파일은 커밋하지 않는다.
2. **빌드 도구:** Windows에 기본으로 있는 .NET Framework 4.x C# 컴파일러(`csc.exe`, C# 5)를
   쓴다. 새 패키지 설치가 없고, 결과물은 분석 VM(Windows 11, .NET Framework 4.8)에서 별도
   런타임 없이 돈다. 빌드 스크립트: `scripts/simulator/Build-WorkbenchSimulator.ps1`.
   이 컴파일러는 빌드 시각을 넣으므로 빌드마다 SHA-256이 다르다. 빌드한 파일 그대로
   Artifact로 등록한다.
3. **내장 프로필:**
   - `loader-like`(인자 없을 때 기본): `%TEMP%`에 실행 코드가 아닌 파일 드롭, HKCU 설정 키와
     Run 값 쓰기, 자식 `cmd.exe /c echo`, `.invalid` 이름 조회, TEST-NET-1(192.0.2.1,
     RFC 5737) 연결 시도(3초).
   - `benign`: `%TEMP%`에 텍스트 파일 쓰기와 읽기.
   - `--plan`: 동작 목록만 출력하고 아무것도 하지 않는다.
4. **무해성:** 현재 사용자 범위만 쓰고, 권한 상승·서비스·드라이버·다운로드·코드 주입이
   없다. 종료 전에 Run 값, 설정 키, 드롭한 폴더를 모두 지운다. 실제 네트워크 목적지는
   예약 주소와 `.invalid` 이름뿐이다. 소스 검사 테스트가 이 경계를 확인한다.
5. **식별 마커:** `WORKBENCH-SIMULATOR-MARKER-v1`. YARA 리허설 룰이 이 문자열을 쓴다.
   마커를 바꿀 때는 버전을 올린다.
6. **결과 매니페스트:** 각 단계 결과를 표준 출력에 JSON 한 줄로 남긴다. VM 실행기는 표준
   출력을 회수하지 않으므로, 실행 증거는 Sysmon 이벤트다.
7. **호스트 실행 금지:** 테스트와 빌드는 컴파일과 정적 검사만 한다. 실행은 분석 VM에서,
   승인 후 `vm run`으로만 한다.

## 결과

- 2026-11-17 VMR-0011: 실제 VM에서 sample 경로가 14단계 모두 성공했다. 프로세스 생성,
  파일 드롭(11)과 삭제(26), Run 값 쓰기(13)와 삭제(12 DeleteValue), 자식 `cmd.exe`(1),
  `.invalid` 조회(22)가 기록됐다. TEST-NET 연결 시도(3)는 네트워크 분리 상태라 기록되지 않았다.
- 같은 Case로 가설 → Sigma·YARA 룰 → 동결 벤치마크 → 검증(TP 1/1, Sigma 정상 TN 1/1)
  → 보고서 → UI를 완주했다(M5 종료 조건).
- JSON 설정 엔진 전환(ADR-006의 후속)은 하지 않았다.
- 예시 룰은 `tools/simulator/rules/`에 있다. 시뮬레이터 전용 리허설 룰이며 최종 채택 룰이
  아니다.
